# 第五章 数据与存储设计

## 5.1 存储总体策略

1. 服务端与桌面端以本机文件为主存储，目录默认位于用户主目录下的 `.bolloon/`，可用环境变量改写根目录。
2. 浏览器端与移动端以本机数据库为主存储（键值存储加对象存储），界面数据不离开本机。
3. 需要跨节点共享的内容（技能包、文档、任务产物、知识条目）以内容寻址方式保存，得到唯一内容标识后即可分享。
4. 密钥类数据（模型密钥、节点私钥、钱包凭证）只存本机，不随会话数据同步，不进入日志。

## 5.3 数据模型要点

1. 会话与消息：会话以标识为主键，消息按时间顺序存储并带类型（用户、助手、工具、系统）、状态与引用关系；分支通过在新会话中复制截至某条的消息序列实现。
2. 目标与运行：目标包含描述、判据、所需技能、状态；运行包含所属目标、状态、检查点、证据与最近一次健康状态。判据含来源（用户给定或软件提出）、是否已确认与版本；证据跨运行汇总。
3. 技能：技能目录包含描述文件（元信息加正文）与引用资料；快照记录名称、版本、内容指纹、来源与冻结时间。
4. 文档：文档以内容标识为主键，附带来源节点、签名、接收时间与解析状态。
5. 知识与记忆：按层组织（人格、项目、会话、知识），条目带来源、时间与置信度，支持多路检索。
6. 关系与目录：好友关系为双向记录；多设备目录以身份标识为主键，记录设备标识、公钥与最近活跃时间。

## 5.4 写入与一致性

1. 原子写入：配置文件与状态文件统一采用「写临时文件 → 原子替换」的方式，避免中断产生半份文件；导入技能等批量操作使用暂存目录加原子替换，失败回滚。
2. 单实例约束：定时任务与监督器通过锁文件保证同一时刻只有一个执行者；锁带过期时间，进程异常退出后可回收陈旧锁。
3. 去重：消息、事件、任务产物均带唯一标识，重复到达按标识去重，避免重复执行副作用。
4. 迁移：旧版配置文件名作为迁移输入读取，迁移结果写入新文件；配置损坏时进入待修复状态并给出修复指引，不静默回退默认值。
5. 兼容：移动端与桌面端数据格式统一，字段新增保持向后兼容，缺失字段按默认值处理。

## 5.5 数据安全与清除

1. 敏感数据（密钥、私钥）单独存放并限制文件权限，界面回显一律脱敏。
2. 软件不采集设备唯一标识、不采集精确定位、不含第三方统计与广告组件。
3. 用户在设置中选择「清除本机数据（注销）」后，删除本机身份与密钥、智能体、会话与消息、支付记录、钱包账本以及本机键值；该操作即时生效。
4. 已写入公开区块链的交易记录无法删除，此限制在隐私政策中已向用户明示。
