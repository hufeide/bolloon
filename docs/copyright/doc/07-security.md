# 第七章 安全与可靠性设计

## 7.1 安全设计目标

1. 用户数据尽可能不出本机：会话、记忆、技能与密钥默认只存本机。
2. 智能体的每一次副作用操作都可解释、可拒绝、可追溯。
3. 网络入站内容默认不可信，验签与校验通过后才进入业务处理。
4. 失败要如实报告，不静默降级、不编造成功。

## 7.2 工具执行安全

1. 参数校验前置：工具执行前校验必填项与类型，参数缺失或类型不符时直接拒绝执行并给出期望格式（例如坐标类参数同时接受数字与数字字符串，避免模型输出字符串导致误判失败）。
2. 权限闸门：所有产生副作用的工具调用经统一闸门判定；默认按「只读放行、写入请示、危险拒绝」策略处理，用户可提高或降低授权级别。
3. 拒绝清单：命令类工具内置拒绝清单，命中即拒绝；拒绝原因写入审计记录。
4. 路径约束：文件类工具限制在本机允许范围内，越权路径直接拒绝；写入采用临时文件加原子替换，避免半份文件。
5. 幂等保护：副作用工具带幂等键，重复调用只执行一次；非幂等操作重放时被守卫拦截。
6. 审计：工具名、参数摘要、执行结论、耗时与调用来源写入操作日志，可按会话检索。

## 7.3 网络与身份安全

1. 身份：节点首次启动生成密钥对与去中心化身份，私钥仅存本机；身份文件损坏时给出修复指引，不静默重建（静默重建会导致身份变更、好友关系失效）。
2. 验签：所有入站消息先验签，验签失败直接丢弃并记录。
3. 重放与重复：消息与事件带唯一标识，重复到达按标识去重；唤醒事件另需通过来源、关联、归属、过期四重校验。
4. 传输安全：跨网段经中继转发时，内容仍以端到端签名为准，中继节点不能伪造内容。
5. 隔离：应用商店版本通过构建变体移除系统级权限通道（无障碍服务与提权通道），仅保留常规能力；直装版本在用户于系统设置中显式授权后才启用。

## 7.4 隐私合规设计

1. 首次启动同意门：同意前不初始化任何功能、不读取本机数据、不连网、不申请权限；选择不同意时停留在说明页，不崩溃、不强制退出、不收集信息。
2. 不收集清单：不要求手机号与邮箱、不收集通讯录与短信、不采集设备唯一标识、不采集精确定位、不含广告与统计组件。
3. 数据流向明示：用户自选的大模型服务商由设备直连，软件不经手内容；托管服务、代码托管、包管理等第三方仅承担下载与防护用途，隐私政策逐项列明。
4. 注销与清除：设置页提供「清除本机数据（注销）」入口，删除身份与密钥、智能体、会话与消息、支付记录与本机键值，即时生效；已上链的交易记录无法删除，此限制事先明示。
5. 权限最小化：仅申请必要权限；移动系统版本高于 11 时不再申请位置权限；相机能力通过系统相机应用完成，不申请相机权限。

## 7.5 可靠性设计

1. 原子写入：配置文件、状态文件、技能导入均保证「要么完整写入，要么保持原状」。
2. 崩溃恢复：长期任务有检查点，进程被强制终止后可从检查点继续；技能导入中断后重启可清理残留并恢复备份。
3. 超时与重试：网络请求、工具执行、外部等待均设超时；可重试错误按退避策略重试，超阈值切换备用或转人工。
4. 熔断：定时任务连续失败触发熔断并暂停，避免无效重试占用资源。
5. 降级：中继不可用时降级为局域网；内容寻址存储不可用时降级为本地模式；事件流不可用时降级为轮询。所有降级都在界面或日志中明示。
6. 不打扰：主任务执行期间与用户设定的安静时段内不触发定时任务，被推迟的任务在主任务结束后补跑。
7. 单实例：调度与监督通过锁文件保证同一时刻仅一个执行者，锁带过期时间，异常退出后可回收。

## 7.6 已知限制与应对

1. 无公网环境：仅能局域网协作，跨网段功能不可用（界面明示，不假装可用）。
2. 依赖外部模型服务：模型服务不可用时对话不可用；已接备用模型与降级路径。
3. 移动端系统授权：无障碍自动操作必须由用户在系统设置中授权，重装应用后需要重新授权（界面给出引导）。
4. 公链不可逆：已上链交易无法撤销，属于协议本身特性，已在隐私政策与界面提示。
5. 第三方组件：点对点网络与内容寻址存储依赖成熟开源组件，其上游缺陷通过版本管理与告警降噪处理；已知上游噪音记录在运行档案中。
