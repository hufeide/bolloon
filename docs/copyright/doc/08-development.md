## 8.2 构建流程

1. 服务端构建：类型检查与编译输出到产物目录，并复制运行时所需的约束文件。
2. 界面构建：浏览器界面与移动端界面分别打包，产物写入产物目录；界面源文件唯一，禁止手改产物。
3. 桌面构建：按桌面配置编译主进程与预加载脚本，再由打包工具生成安装包。
4. 移动端构建：同步本地页面资源到原生工程，再由原生工具链出包；Android 提供完整版与商店版两个构建变体。
5. 命令行构建：编译命令行入口并生成可执行包装脚本。
6. 发布前校验：类型检查、单元测试、模块加载冒烟测试、界面构建，全部通过才允许发布。

## 8.3 开发过程管理

1. 代码约定：类型优先、显式错误处理、可读中文注释；新增功能必须带测试或验收脚本。
2. 质量门禁：提交前自动执行单元测试与类型检查；改代码后需运行类型检查、单元测试、文档校验与界面构建。
3. 验收脚本：对难以用单测覆盖的端到端能力（网络、界面、恢复、权限）编写独立验收脚本，真跑真实组件而非模拟。
4. 文档同步：功能变更需同步更新项目维基页面与变更日志，做到「代码、文档、日志」三者一致。
5. 版本发布：按语义化版本管理，发布时同步升级包版本号、移动端版本号与变更说明。

## 8.6 开发环境与协作

1. 开发环境：支持 macOS、Windows、Linux 三类桌面系统；移动端工程分别在 Android 与 iOS 官方工具链下构建。
2. 协作方式：以版本库为中心，改动通过提交与变更日志留痕；文档与源码同库管理，保证文档与实现同步。
3. 智能体辅助开发：软件自身具备代码读写、命令执行、类型检查与测试能力，可辅助完成开发任务；辅助改动同样受质量门禁约束。
