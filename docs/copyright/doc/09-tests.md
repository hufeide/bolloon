# 第九章 测试情况与结果

## 9.1 测试体系

软件采用三层测试：

1. 单元测试：覆盖模块级逻辑（会话存取、配置迁移、技能导入回滚、目标判据、隐私清除清单、参数校验等），使用 Vitest 运行，共 171 个测试文件、1,912 个测试用例。
2. 端到端验收脚本：覆盖难以用单测模拟的能力（真网络、真浏览器、真文件系统、真子进程、真模型服务），共 42 个脚本，逐个输出通过项计数。
3. 消融实验：对核心能力做「开启与关闭」对照实验，验证能力确实由对应实现带来，而非偶然通过。

## 9.4 消融实验结果

对四项核心能力（文档处理、技能协议、工具调用循环、点对点通信）做开启与关闭对照实验，共 15 项端到端验证全部通过（2026-07-04 记录）。结论：四项能力均在「开启」组可复现地达成预期效果，在「关闭」组如预期失效，说明能力由对应实现提供，而非环境或模型偶然因素。

## 9.5 缺陷管理

1. 缺陷来源：开发自查、验收脚本失败、用户反馈、上架合规核查。
2. 处理原则：先复现再修复；修复必须附带可重跑的验证；同类问题做一次全局排查。
3. 典型已修缺陷（记录在案）：
   - 技能导入未持久化所需技能字段，导致技能门禁空转；
   - 完成判定使用运行开始时的旧快照，运行期间刚满足的判据不可见；
   - 判据处理代码位于不可达分支，导致永远不生成候选判据；
   - 事务导入把内容质量提示误判为结构性失败，导致简洁技能无法导入；
   - 移动端界面层级问题导致弹层被会话页遮挡、按钮看似无响应；
   - 移动端无障碍路径只上报步骤不上报完成，导致界面一直转圈；
   - 网络地址过滤使用尾部匹配，导致移动端取不到可拨入地址；
   - 配置模块导入方式与上游包导出方式不符，导致命令行启动即崩溃。
4. 上游已知噪音：某点对点依赖库在特定版本下会输出无害告警，已降级为提醒级别，不影响功能。

## 9.6 测试可复现性

1. 全部单元测试可用一条命令重跑；类型检查与文档校验同样为单条命令。
2. 端到端验收脚本按其前置说明独立可跑（部分需要真实模型密钥与网络环境，缺失时脚本如实报告跳过项）。
3. 测试与验收的结论均以计数形式输出（通过项、失败项），可直接作为本登记材料的支撑证据。
